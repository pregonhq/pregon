# ADR-0027: Transcription worker and transcript retention
Status: Accepted (implements ADR-0025 §9; refines the Transcript row of ADR-0022)

## Context
After ADR-0024 and ADR-0025 the server accepts segments and keeps them in a persistent queue;
after ADR-0015 and ADR-0012 it has a speech-to-text port with a sidecar behind it. Nothing joined
the two: the queue only grew. This ADR fixes how the queue is drained, where the text goes, and the
one open question the two earlier PRs left: the sidecar client's timeout (`PREGON_STT_TIMEOUT`,
5 min) was longer than the lease a worker held on a job (`PREGON_STT_LEASE`, 2 min), so a slow batch
could lose its jobs to a second worker while still in flight.

## Decision

### One loop per server instance, in capture order, one batch at a time
A `TranscriptionWorker` claims up to the sidecar's batch size from `SegmentQueue`, sends the
batch through `SpeechToText` with the installation's language (`PREGON_LANGUAGE`, ADR-0008) and
reports every job back under the attempt it was claimed with: `complete` for a transcribed
segment, `fail` with the provider's reason for one it could not process. The sidecar batches and
transcription is the bottleneck (ADR-0025), so one loop per instance is enough; a second instance
is a second loop and `FOR UPDATE SKIP LOCKED` keeps them apart. The loop polls every
`PREGON_STT_POLL` (2 s) when the queue is empty; waking on `LISTEN/NOTIFY` stays in ADR-0025's
second step, to be added with a measurement that asks for it.

### The lease outlives the timeout, instead of being renewed
`PREGON_STT_LEASE` defaults to 6 min and the server refuses to start when it is not longer than
`PREGON_STT_TIMEOUT`. The alternative, renewing the lease while a batch is in flight, needs a
heartbeat thread and a new method on the queue port to save a few minutes in the rare case of a
worker that dies mid-batch. The normal case, a batch that ends in seconds, pays nothing either
way. The simple rule is taken first; renewal is a measured change if dead workers ever matter.

### A sidecar that is down does not cost segments their attempts
Every claim counts an attempt (ADR-0025 §9). If the worker kept claiming against a sidecar that
is loading or unreachable, three polls would turn a short outage into `FAILED` segments with
their audio deleted. So when a batch fails as a whole with a retryable error, the worker returns
every job to the queue at once (`fail`, so they are claimable the moment the sidecar is back) and
stops claiming until the sidecar's `/health` reports `UP`, honoring `Retry-After` first. One
outage costs each claimed segment one attempt, not one per poll. A permanent refusal (a `4xx`,
a contract breach) points at a bug on this side: the jobs are failed with the reason, retried up
to the maximum, and the worker pauses one poll so a broken batch does not spin. The port could
grow a `release` that gives the attempt back; that is the queue's design, left to the maintainer.

### Reporting names the tenant; shared ids go in rounds
Segment ids are generated by agents and scoped to a tenant (ADR-0024), so two tenants may use
the same id. The queue port reported by id alone, and a `complete` for one tenant's segment
could have closed the other's. `complete` and `fail` now take the tenant with the id and the
attempt, and the PostgreSQL queue filters on both. The speech-to-text request needs distinct
ids, so a claimed batch that carries one id twice is sent in rounds, one job per id per request,
instead of failing anybody. The contract test fixes both behaviors.

### Transcripts are stored only when retention says so
`PREGON_RETENTION_TRANSCRIPTS` keeps its default `none` (ADR-0006: business events only). With
`none`, a transcribed segment is `TRANSCRIBED`, its audio is gone and its text exists only for
the time it takes the rules to read it, once they exist. With a duration, the worker writes each
transcript to the `transcript` table (V4) and a daily job deletes rows older than the retention.
The table copies the source and the capture window from the segment and references the segment
by value, because the segment's monthly partition is dropped before the transcript may be
(ADR-0025 §8). `UNIQUE (segment_id)` and `ON CONFLICT DO NOTHING` complete ADR-0025 §9's promise
that transcribing twice never duplicates. Spans keep the provider's confidence figures, so the
rules can tell speech from hallucination later (ADR-0001) without transcribing again.

### The state of a segment is readable
`GET /v1/segments/{segmentId}` (Admin API) returns the segment's state, attempt and failure
reason, and its transcript when one is kept. It is the first way to see the pipeline work end to
end without reading the database, and what an operator uses to answer "where did my segment go".
It needs the `admin` scope: an agent's `ingest` key uploads and never reads text.

### Audio retention has one value
`PREGON_RETENTION_AUDIO` accepts only `delete-after-transcription`; the documented alternative, a
duration for debugging, is not implemented and a server given one refuses to start rather than
silently keeping or dropping audio (ADR-0020).

## Consequences
- `docker compose --profile lite up` now transcribes what agents upload: the queue drains at the
  sidecar's speed and the audio is deleted on completion or failure.
- Two new tunables (`PREGON_STT_POLL`, and `PREGON_STT_LEASE` with its new default) and a startup
  check between the lease and the timeout. `deploy/docker-compose.yml` passes `PREGON_LANGUAGE`
  and the two retention variables through from `.env`.
- A sidecar outage costs each segment that was in flight one of its attempts; three outages
  while the same segment sits at the head of the queue fail it. Acceptable for now, visible in
  the status endpoint, and the reason `release` is noted above.
- Transcripts, when kept, are personal data by nature: the retention is the only place where
  Pregón deletes on purpose, and it is off by default.
