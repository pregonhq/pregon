# ADR-0022: Domain model
Status: Proposed

## Context
Phase 1 needs a shared model before any pipeline code is written. It refines the glossary of
`docs/vision.md`. Payloads in `api/openapi.yaml` follow from this ADR.

## Decision

### Three areas, changing at different speeds
- **Configuration**, set by the business: Tenant, ApiKey, Location, Shift, Source, Campaign,
  OfferTarget, OfferItem.
- **Signal**, produced by audio: Segment, Transcript, Interaction, OfferEvent.
- **Read**, computed on demand: OfferRate. KPIs are not stored entities.

### Entities
| Entity | Meaning | Key fields | Persisted |
|---|---|---|---|
| Tenant | The business using Pregón | `id` (`default` in single-tenant installs) | yes |
| ApiKey | Credential of a tenant (ADR-0018) | scopes, hash | yes |
| Location | A branch or store | name, **timezone** (IANA) | yes |
| Shift | Named weekly time windows of a location, e.g. "Morning 06:00-14:00" | name, windows in local time | yes, part of Location |
| Source | A capture point (counter mic, RTSP stream, file) | kind, operating hours, audio pipeline parameters, interaction settings | yes |
| Campaign | What to measure | period `[start, end)` with **optional end**, language, locations in scope | yes |
| OfferTarget | What counts as an offer: a product or a category | name, phrases, synonyms | yes, part of Campaign |
| OfferItem | A member of a category target, e.g. a specific drink | name, synonyms | yes, part of OfferTarget |
| Segment | A speech fragment produced by an agent | id (idempotency key), source, capture start/end, received at | **no**: transient queue only (ADR-0006) |
| Transcript | Text of a segment | text, language, confidence, model | only with transcript retention |
| Interaction | One customer attention | source, start, end, shift, segments, voiced duration | yes |
| OfferEvent | A detected mention of a target in an interaction | campaign, phrase-set version, target, item, matched text, match kind, score | yes; also published as a CloudEvent (ADR-0010) |
| OfferRate | KPI over a time range | see below | no, computed |

### Rules for the whole model
1. Every record carries `tenantId` (ADR-0009). The tenant comes from the API key, never from the
   client (ADR-0018).
2. Identifiers are **UUIDv7**: time-ordered and generated by whoever creates the record without
   asking the server. Agents generate segment ids, which are also the idempotency key.
3. `language` is stored on campaigns, transcripts and offer events (ADR-0008).
4. Audio is never persisted (ADR-0006).
5. **Nothing referenced by history is deleted.** Sources, locations, campaigns and targets are
   archived, so interactions, offer events and past KPIs stay readable.

### Decisions
- **Shifts** are fixed named windows per location, so "per shift" means the same for every
  source of a location. An interaction belongs to the shift in which it starts.
- **Campaigns** may be seasonal (with an end) or permanent (no end, active until archived).
  The KPI is always queried for a time range, so both behave the same.
- **Offer targets** make one model serve both "pan de muerto" and "drinks or desserts":
  - a product target has phrases and synonyms and no items;
  - a category target has generic offer phrases ("algo de tomar") and items ("agua de jamaica",
    "café"), each with synonyms;
  - mentioning a phrase of the target, or any of its items, counts as an offer of that target.
    The OfferEvent records the item when one matched.
- **Phrase sets are versioned.** Editing the phrases, synonyms or items of an active campaign
  creates a new version; each OfferEvent records the version that detected it, so results
  before and after an edit are not silently mixed.
- **Interactions are grouped by capture time, not arrival time.** Agents retry uploads, so
  segments may arrive late or out of order. Consecutive segments of a source belong to the same
  interaction while the silence gap between them is below the source's gap threshold. An
  interaction is closed only after a watermark (gap threshold plus a configurable allowed
  lateness) has passed. A segment that arrives after its interaction was closed is recorded
  and counted, not silently dropped; the exact handling is part of the interaction design.
- **Minimum voiced duration.** An interaction with less voiced time than a per-source minimum
  (a cough, a lone "thanks") is not counted in KPIs.
- **Clocks.** Capture times come from the agent, which must keep its clock synchronized (NTP).
  The server also records arrival time and flags segments whose difference exceeds a threshold.

### Offer rate
For a campaign, a time range and a grouping (source, shift):
`interactions with at least one OfferEvent of the campaign / counted interactions`,
where counted interactions are those within the campaign's period and locations, inside the
source's operating hours, and above the minimum voiced duration. A breakdown per target
(and per item) is available with the same denominator.

### Detection across the cascade (ADR-0001)
| Tier | Detects | When |
|---|---|---|
| Rules | Phrases, synonyms and item names, including fuzzy matches | MVP |
| Local embeddings | Paraphrases close to a target's phrases ("¿y para acompañar?") | later |
| LLM (ADR-0012) | Offering versus merely mentioning ("¿gusta una coca?" vs "la coca cuesta 20") | later, only for undecided cases |

Known MVP limitation: rules detect **mentions**, not intent. "Ya no hay flan" counts as a
dessert offer. The semantic tiers exist to correct this.

### Future, not decided here
- A tenant catalog synchronized from the adopter's POS menu, so category items do not have to
  be typed by hand.
- Interactions defined by POS tickets instead of silence gaps (ROADMAP, later phases).

## Consequences
One target model covers seasonal products and permanent categories. KPIs remain comparable
across phrase edits and stable under retries. The interaction grouping, the watermark and the
KPI calculation are maintainer-designed pieces; this ADR fixes their inputs and invariants,
not their algorithms.
